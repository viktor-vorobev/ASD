ДОКУМЕНТАЦИЯ ПО ПРОЕКТУ: СТРУКТУРЫ ДАННЫХ И РЕАЛИЗАЦИИ ТАБЛИЦ НА C++

1. АРХИТЕКТУРА И СТРУКТУРА ПРОЕКТА

Проект разделен на три основных логических уровня:
  1. Абстрактный интерфейс таблиц (ITable).
  2. Базовые структуры данных (Списки, Деревья, Хэш-таблицы), выступающие в роли
     контейнеров для хранения данных.
  3. Математические объекты (Monom, Polynom), которые могут использоваться в качестве
     ключей или значений в таблицах.

Список файлов и их назначение:
  - itable.h / itable.cpp - Базовый интерфейс ITable и класс исключения TableException.
  - list.h - Шаблонный двусвязный список List<T>.
  - binary_tree.h - Шаблонное универсальное бинарное дерево BinaryTree<T>.
  - bst.h - Бинарное дерево поиска BST<K, V>.
  - avl_tree.h - Сбалансированное AVL-дерево поиска AVLTree<K, V>.
  - rb_tree.h - Красно-черное дерево поиска RBTree<K, V>.
  - monom.h / monom.cpp - Класс монома (коэффициент и степени переменных).
  - polynom.h / polynom.cpp - Класс полинома (хранится как список мономов).
  
Реализации таблиц:
  - unsorted_table_arr.h - Неотсортированная таблица на массиве (std::vector).
  - sorted_table_arr.h - Отсортированная таблица на массиве с бинарным поиском.
  - unsorted_table_list.h - Неотсортированная таблица на базе связного списка List.
  - unsorted_table_tree.h - Неотсортированная таблица на базе BinaryTree.
  - sorted_table_bst.h - Отсортированная таблица на базе дерева поиска BST.
  - sorted_table_avl.h - Отсортированная таблица на базе AVL-дерева.
  - sorted_table_rb.h - Отсортированная таблица на базе Красно-черного дерева.
  - hash_table_chain.h - Хэш-таблица с методом цепочек (Chaining).
  - hash_table_double.h - Хэш-таблица с открытой адресацией (двойное хэширование).

2. ОПИСАНИЕ БАЗОВОГО ИНТЕРФЕЙСА `ITable<TKey, TVal>`

Интерфейс представляет собой чисто виртуальный класс, задающий единый контракт для
всех видов таблиц.

Основные методы:
  - void insert(const TKey& key, const TVal& value)
    Добавление новой пары ключ-значение. Если ключ уже существует, генерируется TableException.
  
  - void remove(const TKey& key)
    Удаление записи по ключу. Если ключ не найден, генерируется TableException.
  
  - TVal find(const TKey& key) const
    Поиск значения по ключу. Возвращает копию значения или бросает исключение.
  
  - bool contains(const TKey& key) const
    Проверка наличия ключа в таблице (возвращает true/false).
  
  - void clear()
    Очистка таблицы и освобождение памяти.
  
  - bool isEmpty() const
    Проверка таблицы на пустоту.
  
  - int size() const
    Возвращает текущее количество элементов в таблице.
  
  - std::vector<TKey> getKeys() const
    Получение списка всех ключей таблицы в виде вектора.
  
  - std::vector<TVal> getValues() const
    Получение списка всех значений таблицы в виде вектора.
  
  - TVal& operator[](const TKey& key)
    Оператор доступа по ключу. Если ключ отсутствует, создается элемент со значением по умолчанию.
  
  - const TVal& operator[](const TKey& key) const
    Константный оператор доступа. Бросает исключение, если ключ не найден.

Класс исключения:
  TableException наследуется от std::runtime_error и используется для обработки ошибок
  (дублирование ключей, отсутствие ключа при удалении/поиске).

3. АНАЛИЗ РЕАЛИЗАЦИЙ ТАБЛИЦ И СТРУКТУР ДАННЫХ

3.1. Таблицы на линейных структурах (Массивы и Списки)
  * UnsortedTableOnArr (Неотсортированная на массиве):
    Данные хранятся в std::vector<std::pair<TKey, TVal>>. Вставка выполняется за O(1)
    в конец, но требует предварительной проверки уникальности за O(N). Поиск и удаление
    требуют полного сканирования массива (O(N)). При удалении используется оптимизация:
    текущий элемент замещается последним элементом вектора, после чего вызывается pop_back().
    
  * SortedTableOnArr (Отсортированная на массиве):
    Элементы хранятся в отсортированном по ключу порядке. Для поиска используется бинарный
    алгоритм через std::lower_bound, что обеспечивает скорость поиска O(log N). Однако,
    вставка и удаление требуют сдвига элементов массива, что занимает O(N) времени.
    
  * UnsortedTableOnList (Неотсортированная на списке):
    Использует кастомный двусвязный список List<std::pair<TKey, TVal>>. Все основные операции
    (поиск, вставка, удаление) имеют сложность O(N), так как требуют последовательного обхода.

3.2. Таблицы на древовидных структурах
  * UnsortedTableOnTree (Неотсортированная на универсальном дереве):
    Использует общий класс BinaryTree без соблюдения свойств упорядоченности ключей.
    Поиск осуществляется полным обходом дерева (например, в ширину через очередь), что
    делает операции неэффективными — O(N).
    
  * SortedTableOnBST (На дереве поиска):
    Классическое дерево поиска. В среднем случае операции выполняются за O(log N). В худшем
    случае (при вставке отсортированных данных) дерево вырождается в связный список, и
    сложность возрастает до O(N).
    
  * SortedTableOnAVL (На AVL-дереве):
    Сбалансированное по высоте дерево поиска. Разность высот поддеревьев любого узла не
    превышает 1. Балансировка выполняется с помощью малых и больших вращений (left/right rotate).
    Гарантирует сложность O(log N) для поиска, вставки и удаления в любых ситуациях.
    
  * SortedTableOnRB (На Красно-черном дереве):
    Сбалансированное дерево, использующее окраску узлов (RED/BLACK) и правила ветвления.
    Максимальная высота дерева не превышает 2 * log(N + 1). Обеспечивает строгую сложность
    O(log N) на все операции и обычно показывает более быструю вставку/удаление на практике
    по сравнению с AVL за счет меньшего числа вращений.

3.3. Хэш-таблицы
  * HashTableChaining (Метод цепочек):
    Массив списков (динамическое разрешение коллизий). Индекс вычисляется через std::hash.
    При превышении коэффициента заполнения (load factor >= 0.75) происходит рехэширование
    (увеличение размера таблицы в 2 раза + 1). В среднем операции занимают O(1).
    
  * HashTableDouble (Двойное хэширование):
    Использует открытую адресацию. При коллизии вычисляется шаг сдвига с помощью второй хэш-функции:
    hash2(key) = p - (hash(key) % p). Ячейки имеют статусы EMPTY, OCCUPIED, DELETED.
    Эффективно расходует память, но чувствительно к коэффициенту заполнения.

4. СРАВНИТЕЛЬНАЯ ТАБЛИЦА СЛОЖНОСТИ ОПЕРАЦИЙ

Обозначения: N — текущее количество элементов в таблице.

+-----------------------+-------------------+-------------------+-------------------+
| Тип таблицы           | Поиск (Find)      | Вставка (Insert)  | Удаление (Remove) |
|                       | Med / Worst       | Med / Worst       | Med / Worst       |
+-----------------------+-------------------+-------------------+-------------------+
| UnsortedTableOnArr    | O(N)   / O(N)     | O(N)* / O(N)* | O(N)   / O(N)     |
| SortedTableOnArr      | O(log N)/O(log N) | O(N)   / O(N)     | O(N)   / O(N)     |
| UnsortedTableOnList   | O(N)   / O(N)     | O(N)* / O(N)* | O(N)   / O(N)     |
| UnsortedTableOnTree   | O(N)   / O(N)     | O(N)* / O(N)* | O(N)   / O(N)     |
| SortedTableOnBST      | O(log N)/ O(N)    | O(log N)/ O(N)    | O(log N)/ O(N)    |
| SortedTableOnAVL      | O(log N)/O(log N) | O(log N)/O(log N) | O(log N)/O(log N) |
| SortedTableOnRB       | O(log N)/O(log N) | O(log N)/O(log N) | O(log N)/O(log N) |
| HashTableChaining     | O(1)   / O(N)     | O(1)   / O(N)     | O(1)   / O(N)     |
| HashTableDouble       | O(1)   / O(N)     | O(1)   / O(N)     | O(1)   / O(N)     |
+-----------------------+-------------------+-------------------+-------------------+

*Примечание: Для неотсортированных таблиц вставка в конец занимает O(1), однако интерфейс 
требует уникальности ключей, из-за чего перед вставкой выполняется поиск дубликата за O(N).
